# Личный сайт — Казим Давидов (проектное управление и консалтинг)

Статический сайт без сборки и зависимостей: чистый HTML, CSS и немного JS.
Разворачивается бесплатно на **Cloudflare Pages** (или Netlify / GitHub Pages).

## Структура

```
site/
├─ index.html                  Главная
├─ about.html                  Обо мне, опыт, навыки, резюме
├─ services.html               Услуги
├─ cases.html                  Кейсы (10 разборов)
├─ blog.html                   Список статей
├─ contacts.html               Контакты и форма
├─ resume.html                 Резюме для печати / PDF (скрыто: не в меню, ссылку даёте вручную)
├─ 404.html                    Страница ошибки
├─ robots.txt                  Для поисковых систем
├─ sitemap.xml                 Карта сайта
├─ _headers                    Заголовки безопасности (Cloudflare)
├─ .nojekyll                   Отключает обработку Jekyll на GitHub Pages
├─ articles/
│   ├─ pmo-failures.html
│   ├─ audit-2-weeks.html
│   └─ pmo-vs-project-office.html
└─ assets/
    ├─ css/style.css
    ├─ js/main.js
    └─ img/favicon.svg
```

## Как посмотреть локально

Просто откройте `site/index.html` двойным щелчком в браузере — сайт работает без сервера.

Если хотите локальный сервер (опционально), подойдёт любой из вариантов:
- VS Code → расширение **Live Server** → «Open with Live Server».
- Или `npx serve site` (если установлен Node.js).

## Публикация на Cloudflare Pages (бесплатно, ~5 минут)

1. Зарегистрируйтесь на https://dash.cloudflare.com (аккаунт бесплатный).
2. В меню выберите **Workers & Pages → Create → Pages → Upload assets**.
3. Введите имя проекта, например `kazim-davidov`. Это даст адрес
   `https://kazim-davidov.pages.dev`.
4. Перетащите в окно **содержимое папки `site`** (именно файлы внутри `site`,
   чтобы `index.html` оказался в корне).
5. Нажмите **Deploy**. Через минуту сайт будет доступен по адресу `*.pages.dev`.

Дальше при любых правках: снова загрузите обновлённую папку (или подключите
GitHub‑репозиторий — тогда деплой будет автоматическим при каждом коммите).

### Вариант с авто‑деплоем через GitHub (Git integration)

Cloudflare Pages умеет подключаться к репозиторию: тогда каждый коммит
публикуется сам, а для веток создаются превью‑адреса. Репозиторий может быть
**приватным** — в отличие от GitHub Pages.

1. Залейте **содержимое папки `site`** в репозиторий GitHub (см. раздел про
   GitHub Pages ниже — те же шаги загрузки).
2. В Cloudflare: **Workers & Pages → Create → Pages → Connect to Git**.
3. Авторизуйте GitHub и выберите репозиторий. **Production branch** = `main`.
4. Настройки сборки (сайт без сборки):
   - **Build command** — оставьте пустым (или `exit 0`);
   - **Build output directory** — `/`.
5. **Save and Deploy**. Адрес — `https://<имя-проекта>.pages.dev`.

Режим выбирается один раз при создании проекта: у готового проекта сменить
Git‑интеграцию на загрузку drag‑and‑drop (Direct Upload) или обратно нельзя —
при необходимости просто создайте новый проект. Автодеплой можно отключить в
настройках, если он не нужен.

## Публикация на GitHub Pages (бесплатно)

Важно: на бесплатном тарифе GitHub Pages публикуется только из **публичного**
репозитория — файлы сайта будут видны. Для личного сайта, который вы и так
показываете по ссылке, это нормально.

Git устанавливать не обязательно — файлы можно загрузить через браузер.

### Вариант 1. Через сайт GitHub (без установки программ)

1. Зарегистрируйтесь на https://github.com.
2. **New repository**. Имя, например `kazim-davidov`, тип — **Public**,
   галочки «Add a README» не ставьте.
3. На странице пустого репозитория: **Add file → Upload files**.
4. Перетащите **содержимое папки `site`** (файлы и папки `assets`, `articles`,
   `index.html` и т. д.), но **не саму папку `site`** — `index.html` должен
   оказаться в корне репозитория.
5. **Commit changes**.
6. **Settings → Pages**. Build and deployment: Source = **Deploy from a branch**,
   Branch = **main**, папка = **/ (root)**. Нажмите **Save**.
7. Через 1–2 минуты сайт откроется по адресу
   `https://<ваш-логин>.github.io/kazim-davidov/`.

Если назвать репозиторий `<ваш-логин>.github.io`, адрес будет короче —
`https://<ваш-логин>.github.io/`.

### Вариант 2. GitHub Desktop (удобнее для повторных правок)

1. Установите GitHub Desktop (https://desktop.github.com) и войдите в аккаунт.
2. **Create repository** → укажите папку `site` как локальную папку репозитория.
3. Commit → **Publish repository** (снимите галочку «Keep this code private»).
4. В **Settings → Pages** включите публикацию с ветки `main`, папка `/ (root)`.
5. При правках: Commit → Push, сайт обновится автоматически.

Файл `.nojekyll` в корне уже создан — он отключает обработку Jekyll, чтобы все
файлы отдавались как есть.

## Свой домен (опционально)

1. Купите домен (удобно у российских регистраторов: reg.ru, nic.ru).
2. В Cloudflare Pages → ваш проект → **Custom domains → Set up a domain**.
3. Следуйте инструкциям (пропишите NS‑серверы или CNAME у регистратора).

## После запуска — чтобы сайт находили

1. Добавьте сайт в **Яндекс.Вебмастер** (webmaster.yandex.ru) и подтвердите права.
2. Добавьте в **Google Search Console** (search.google.com/search-console).
3. Отправьте `sitemap.xml` в обоих сервисах.
4. Разместите ссылку на сайт: в резюме, профиле hh.ru, LinkedIn, Telegram, подписи в письмах.

## Как добавлять статьи

1. Скопируйте любой файл из `articles/` как шаблон.
2. Создайте новый файл, например `articles/moya-statya.html`, поменяйте `<title>`,
   описание и текст.
3. Добавьте карточку статьи в `blog.html` (скопируйте блок `<div class="post">`).
4. Добавьте ссылку в `sitemap.xml`.
5. Загрузите обновлённую папку на Cloudflare Pages.

## Заметки по конфиденциальности

- Официально на сайте открыто названы только **«Алабуга»** и **БРИКС**.
- Остальные работодатели и партнёры обезличены: организация не называется, детали обобщены.
- Рекомендую и дальше придерживаться правила: **называть компанию только там, где
  это не нарушает обязательств**, а суммы и внутренние детали давать в округлённом виде.
- В статьях не публикуйте персональные данные третьих лиц и коммерческую тайну.
